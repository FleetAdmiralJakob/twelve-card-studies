Estimated decoded image surface bytes = natural width × natural height × 4, summed once per unique image source observed by that point. Natural dimensions are density-corrected; responsive source files can contain more pixels. This is an RGBA surface estimate, not actual process or GPU memory. It excludes font memory, CSS background images, browser bookkeeping, extra decoded copies and other rendering surfaces. A measured zero is valid; a missing estimate is unavailable.

SVG nodes inside an image are not live HTML document elements. CSS drawing elements do count in the DOM. The resulting counts do not establish equivalent rendering or memory costs. Image counts and unique-source counts after the workload are also preserved in the raw run details.

Environment and method

Results belong to the recorded machine, engine, files and workload. This report uses only the two embedded four-edition datasets; it does not mix in earlier benchmarks or separate experiments.

Environment
No completed dataset embedded.

Run counts and order balance will be shown from the selected dataset.

Fresh contexts, shared machine

The protocol uses a fresh browser context per run, headless mode and device-pixel ratio 1, with no CPU or network throttling. A fresh context is not a fresh browser process or operating system cache. Process isolation is off, and the machine is not isolated from other work. “Cold” describes this protocol’s first-load snapshot, not a guarantee of an untouched machine.

The same interaction sequence

The common workload first opens all twelve cards, then makes twelve next-card changes over 180 animation frames with the cards warmed. It samples 180 scroll frames when there is enough vertical overflow. Exact recorded workload settings, baseline frame intervals, synchronous handler timings, individual first opens and functional checks are included in the run details.

Two engines, two viewports

Windows WebKit is not Safari on a Mac. It is an additional engine test on this machine. A mobile viewport tests the responsive layout; it does not emulate a physical phone’s CPU, network or display. Headless callback timings do not establish display FPS.

What this report can establish

The data can describe the supplied editions under the recorded conditions. It cannot establish a universal performance winner or visual equivalence. Only a Discord message was supplied, not an actual site or implementation to inspect; this report makes no verdict about that implementation.
